# Tars 工业级企业应用（B2B SQM）UI/UX 设计系统与前端架构准则

本准则融合业界高星设计系统（Ant Design 企业级设计价值观、Linear 极简信噪比原则、Microsoft Fluent UI / Apple HIG 防御性排版准则），专为质量与供应商管理系统定制，确保界面**简洁、清晰、合理、高信噪比且永不破版**。

---

## 一、 核心设计价值观与哲学（Core Philosophy）

1. **自然直观（Natural）**：界面严格围绕制造质量与供应链业务心智组织，直接呈现业务实体，严禁向用户直抛底层开发术语与代码标记。
2. **确定可期（Certainty）**：空间与交互具有极高确定性。布局绝不随文本长短出现意外破版、文字混乱折行或弹出难看的水平滚动条。
3. **克制至简（Restraint / 高信噪比）**：**视觉噪音是系统最大的敌人**。界面每一寸空间都应分配给核心决策数据，非关键指标坚决下放。

---

## 二、 关键 UI/UX 架构与排版规范（UI/UX Architecture Rules）

### 1. 信息信噪比与渐进式呈现规范（Signal-to-Noise Ratio & Progressive Disclosure）
- **第一视图只展示高价值信号**：
  - 在卡片（Card）、快捷胶囊（Capsule）、目录树（Tree）等高频浏览的第一触达层，**只保留“业务图标 + 核心名称 + 关键状态徽标（如已生效/草稿）”**。
- **次要与统计数据坚决下放**：
  - 诸如“字数（如 1452字）”、“文件字节大小（如 24KB）”、“作者工号”、“技术ID”等非决定性指标，**严禁堆砌在卡片或第一视图表面**造成视觉污染；
  - 次要信息统一遵循“渐进式呈现”原则，收拢至**右侧详细快照面板（Inspector）、详情抽屉（Drawer）或按需展开的面板**中供深度查看。

### 2. 文本排版与防御性截断规范（Typography & Defensive Truncation）
- **卡片标题强制单行截断（Single-Line Ellipsis）**：
  - 在网格卡片、文件列表标题、操作胶囊等定宽/自适应单元中，文本**严禁无序自动折行**，必须统一配置：
    ```css
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
    width: 100%;
    ```
  - 避免因为一个 8 个字的名字折为两行导致同排卡片忽高忽低、排版错乱破碎。
- **信息无损可达原则（Tooltip Guarantee）**：
  - 凡使用了 `ellipsis` 省略截断的文本，**必须强制绑定原生 `title` 属性或带延迟的 `<el-tooltip>`**，保证用户鼠标悬浮时能清晰查阅 100% 完整长名称。

### 3. 语言纯洁性与业务本土化规范（Domain Language Purity）
- **全量清除多余英文与技术标记**：
  - 界面禁止出现中英文夹杂、面向开发者的扩展名与括号代码，如 `(New)`, `(VIEWS)`, `(Favorites)`, `(.doc)`, `(.lnk)` 等，一律净化为典雅的中文（如：`质量规程文档`、`分类目录`、`跨项目标准引用`）。
- **行业标准代号白名单**：
  - 仅保留全球工业制造通用的标准化质量术语缩写（如 **CTQ, CPK, IQC, 8D, FMEA, PPAP, APQP, MSA, SPC, SOP**），其余所有系统菜单、操作动作、状态胶囊、提示反馈 100% 采用专业、精准的中文。

### 4. 防御性容器与零滚动条铁律（Defensive Container & Zero-Scrollbar）
- **零意外横向滚动条（Zero Horizontal Scrollbar Rule）**：
  - 侧边栏、属性预览面板、详情抽屉等垂直容器，根层必须显式配置 `overflow-x: hidden;`，杜绝任何因子元素尺寸微小溢出而产生丑陋的横向滚动条。
- **操作按钮组分层自适应排布**：
  - 在宽度有限（< 360px）的容器内，**严禁将 3 个以上的文字按钮横向紧密并排**；
  - 必须采用**主次分层结构**：
    - 主操作层（行1）：核心业务按钮（Primary 蓝色，自适应 flex: 1） + 辅助模式（如 `↗ 新标签页`）；
    - 增值/扩展层（行2）：次级功能（如 `✨ AI 智能伴写`）采用全宽微质感浅色按钮；
    - 在 240px ~ 480px 任何拖拽与屏幕尺寸下，必须 100% 完美自适应且永不溢出。

### 5. 提示与反馈规范（Tooltips & Feedback）
- **Tooltip 统一 0.5s 防闪烁延迟**：
  - 所有 `<el-tooltip>` 必须显式配置 `:show-after="500"`，避免鼠标滑过屏幕时黑色提示框频繁闪烁造成“打灯笼”式的视觉疲劳。
- **操作反馈分级**：
  - **静默/高频操作**（如文本自动保存、标星点亮）：使用行内微状态灯（如“已保存 11:42”）或微动画，不弹全局弹窗；
  - **常规交互**：使用轻量 `ElMessage.success()` 提供准确中文反馈；
  - **破坏性/高危操作**（如删除标准文件、清除预设）：强制调用 `ElMessageBox.confirm()` 进行二次中文确认，并明确标注受影响对象的完整名称。

## 三、 表格与数据呈现规范（Data Table & Grid）

1. **统一组件**：数据列表必须使用项目封装的 `DataTable` 组件，严禁在页面上手写裸 `el-table`。
2. **操作列与主键**：操作列一律固定在右侧 (`fixed="right"`)；编码/主键列居中或固定在左侧 (`fixed="left"`)。
3. **行内快捷编辑**：对于高频更新字段（如配合度、备注、等级），应通过 `editable: true` 支持单元格双击行内快编，失焦或回车即刻保存，减少弹窗打扰。
4. **日期与时间标准**：业务列表中的日期一律展示为 `YYYY-MM-DD` 格式；审计日志或操作痕迹一律展示为 `YYYY-MM-DD HH:mm:ss`；空值统一以中划线 `-` 占位。

---

## 四、 务实工程与防过度设计铁律（Engineering Discipline）

1. **范围严控（Scope Control）**：仅修改用户明确指示的文件与功能模块。严禁顺带“重构”或修改相邻未要求的文件。
2. **YAGNI 原则（You Aren't Gonna Need It）**：绝不为了“未来可能的需求”编写多层抽象、设计模式、复杂工厂或泛型多重包装。
3. **依赖务实把控（Pragmatic Dependencies）**：禁止滥加琐碎微型包；遇到复杂专业领域（如复杂富文本、复杂图表）主动采用行业成熟方案并向用户说明。
4. **最简路径优先（Simplest Path First）**：能用 3 行代码解决的绝不写 30 行；能放在现有单文件内解决的绝不新建跨层目录。
5. **保持现有风格一致**：严格遵循项目中已有的命名、样式结构与 API 规范，不做风格分裂。
